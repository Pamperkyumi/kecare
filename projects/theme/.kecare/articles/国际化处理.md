# 国际化处理

Kecare 在构建时调用 LLM 将文章翻译成多种语言，每种语言各生成一个独立的文章页面。翻译结果按段落缓存，文章未改动或只改动部分段落时，只有改动过的段落会重新请求模型。

## 启用翻译

在文章的 Front Matter 中添加 `translate` 字段：

```yaml
---
title: 我的第一篇文章
date: 2026-03-01
translate: ['zh-CN', 'en-US', 'ja-JP']
---
```

规则如下：

- 数组的**第一个**语言代码是文章的原始语言，原文直接渲染、不做翻译，其余语言依次交给 LLM 翻译
- 未填写 `translate` 时默认为 `['en-US']`
- 语言代码须形如 `zh-CN`（小写语言 + 大写地区，地区可省略），不合法会在生成时报错并中断
- 声明了多个语言但未配置 LLM 时，生成同样会中断并提示缺少配置

各语言页面的输出路径由主题的 `*.article.ts` 模板决定，例如 `articles/<lang>/<hash>`。

## 配置 LLM

在 `.kecare` 目录下新建 `kecare.config.ts`：

```ts
export async function kecareConfig() {
    return {
        llm: {
            provider: 'OpenAI', // 或 'Anthropic'
            model: 'deepseek-chat',
            apiKey: 'your-api-key',
            apiBaseUrl: 'https://api.deepseek.com/',
            prompt: '' // 额外提示词，可留空
        }
    };
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| `provider` | 是 | `'OpenAI'` 或 `'Anthropic'`，区分大小写 |
| `model` | 是 | 模型名称 |
| `apiKey` | 是 | API 密钥 |
| `apiBaseUrl` | 是 | API 地址 |
| `prompt` | 是 | 附加提示词，拼接在内置系统提示词之后，可传空字符串 |
| `maxTokens` | 否 | 单次请求的输出上限，仅 Anthropic 生效，默认 1024 |

任何兼容 OpenAI 或 Anthropic API 格式的服务都可以使用，例如 DeepSeek、通义千问的 OpenAI 兼容端点。

## 翻译过程

翻译按段落进行，Kecare 会先做几件事：

1. 代码块（` ``` ` 围栏）被替换成占位符，不参与翻译，翻译完成后原样还原
2. 标题单独翻译一次，与正文分开缓存
3. 正文按空行切分成段落，逐段请求模型

内置系统提示词会要求模型保留 HTML / Markdown 标签和属性，不改动链接 `href`、图片 `src`、`id`、`class`。`prompt` 字段的内容拼接在其后，可用于补充术语表、语气之类的自定义要求。

模型请求失败时（网络错误、余额不足等），该段落回退为原文渲染，且**不写入缓存**，下次构建会重新尝试翻译，不会把失败结果永久固化。

## 缓存

翻译相关的缓存都在 `.kecare/cache` 目录下：

- `translations/<lang>/<标题哈希>/translations.json`：段落级译文缓存，键为段落内容的哈希。改动一篇文章的某个段落，只有该段会重新翻译
- `markdown-manifest.json`：文章级缓存，记录原文内容哈希与已生成的页面。文章未改动且产物齐全时，构建直接跳过解析与翻译；产物文件被删后会用缓存数据重建页面

`kecare clean` 会清理生成产物与文章级缓存，但保留 `translations` 下的段落译文。想彻底重置全部缓存，删除 `.kecare/cache` 目录即可。

## 常用语言代码

| 语言 | 代码 |
|------|------|
| 简体中文 | `zh-CN` |
| 英语 | `en-US` |
| 日语 | `ja-JP` |
| 韩语 | `ko-KR` |
| 繁体中文 | `zh-TW` |

语言代码遵循 BCP 47 标准的 `语言-地区` 形式，如 `en-GB`、`pt-BR`，地区部分需大写。
