# 👋Hello Kecare

Kecare 是一个面向多语言内容创作的静态站点生成器。它的核心理念是**非侵入式设计**——把内容系统从主题与前端框架中彻底解耦出来。

你可以把 Kecare 理解为一台"编译器"：它读取你的 Markdown 文章，执行翻译、缓存、分批调度等一系列构建期处理，最终把页面文件交给任意一个文件路由型的前端框架去渲染。渲染框架只是"宿主"，而不是 Kecare 的一部分——这意味着你的内容资产永远不与某个特定框架的生死绑定。

Kecare 由 Bun 驱动，以独立 CLI 的形式分发。用户全局安装一个 kecare 命令，就获得了完整的生成能力，而无需在项目里为"生成"这件事安装任何依赖。

## 为什么选择 Kecare？

「告诉你两件好事吧」：

- 第一，它把**多语言**做成了构建期的一等公民——你的每一篇文章都可以在构建时被自动翻译成多种语言，而不是依赖运行时的语言切换组件。
- 第二，它把**选择权**还给了你——生成器与渲染框架分离，主题自带完整技术栈，你可以随时带着全部内容迁移到任何你喜欢的宿主框架上。

当你使用Vue时，你就能享受到Vue带来的现代开发体验与预渲染静态输出

当你使用React时，你就能借助Next.js得到组件生态与服务端渲染的成熟方案

当你使用Svelte时，你就能换来更小的产物体积与没有虚拟DOM负担的运行时

当你使用PHP时，你就能像过去那样用最朴素的方式输出页面，让任何一台支持PHP的主机都成为你的博客

甚至当你只想用原生HTML时，Kecare也能交给你最纯净的静态页面。

它只负责"编译"——把 Markdown 变成结构化的多语言数据，再把数据交给模板文件生成最终的页面文件。至于这些页面文件交给谁来渲染，Kecare 完全不过问。今天放在 Nuxt 里用 Vue 渲染，明天想试试 Next.js 或 SvelteKit，只需要按新框架的语法重写一套模板文件，你的全部文章内容一个字都不用改。

内容是你的资产，框架只是过客。

所以去与其他博客框架来进行对比，对Kecare来说，似乎毫无意义
