# 为什么选择 Kecare

## 什么是 Kecare？

Kecare 是一个面向多语言内容创作的静态站点生成器。它的核心理念是**非侵入式设计**——把内容系统从主题与前端框架中彻底解耦出来。

你可以把 Kecare 理解为一台"编译器"：它读取你的 Markdown 文章，执行翻译、缓存、分批调度等一系列构建期处理，最终把页面文件交给任意一个文件路由型的前端框架去渲染。渲染框架只是"宿主"，而不是 Kecare 的一部分——这意味着你的内容资产永远不与某个特定框架的生死绑定。

Kecare 由 Bun 驱动，以独立 CLI 的形式分发。用户全局安装一个 kecare 命令，就获得了完整的生成能力，而无需在项目里为"生成"这件事安装任何依赖。

## 为什么选择 Kecare？

「告诉你两件好事吧」：

- 第一，它把**多语言**做成了构建期的一等公民——你的每一篇文章都可以在构建时被自动翻译成多种语言，而不是依赖运行时的语言切换组件。
- 第二，它把**选择权**还给了你——生成器与渲染框架分离，主题自带完整技术栈，你可以随时带着全部内容迁移到任何你喜欢的宿主框架上。

下面把 Kecare 与现有的主流方案做个对比。

### Hexo / Hugo / Jekyll

Hexo 生态成熟，但工作流与开发体验已经落后于现代前端工程：没有类型提示、插件体系陈旧、模板引擎与前端框架脱节。Kecare 的模板就是普通的 TypeScript 文件，编写体验与写前端代码完全一致，全程有类型护航。同时 Kecare 的构建管线是开放的——翻译、缓存、调度这些能力都是生成器内建的，而不是需要你自行拼装插件的"可选件"。

### VitePress / VuePress

VitePress 是出色的文档工具，但它为文档打造，缺少面向博客与内容站的集成：菜单系统、归档页、列表分页、多语言翻译在 VitePress 里都需要自行搭建。而这些在 Kecare 里都是生成器开箱提供的模块——主题作者声明模板，生成器负责调用与产出。

### Valaxy

Valaxy 与 Kecare 是最接近的同类：两者都追求现代开发体验与预渲染静态输出。区别在于架构哲学——Valaxy 是框架一体化，自己就是构建工具，主题以 npm 组件包的形式存在；Kecare 是**生成器与框架分离**，主题是一个自带完整前端技术栈的项目模板。前者换框架等于换整个站点，后者换宿主只需换渲染层，内容管线原封不动。此外，Valaxy 的国际化是运行时单页切换，而 Kecare 在构建期就产出每种语言独立的静态页面——每种语言都有真实 URL，对搜索引擎更友好。

### Astro

Astro 的群岛架构擅长内容与交互的混合页面，首屏性能优秀。但它是通用 Web 框架，多语言内容的产出依旧需要社区方案拼接。Kecare 专注内容站点场景：翻译管线、内容寻址、增量缓存都是核心能力而非外围生态。

## Kecare 的亮点

### 构建期 AI 多语言翻译

在文章的 Front Matter 中声明 `translate: ['zh-CN', 'en-US', 'ja-JP']`，构建时 Kecare 会调用 OpenAI / Anthropic 兼容接口自动完成翻译。翻译系统包含两件工程保障：

- **双层缓存**：文章级的内容哈希清单跳过未变更文章；段落级哈希缓存让只改动一段的重新翻译也只发生在那一段。
- **代码块保护**：翻译过程中代码块被占位符隔离，绝不会被翻译引擎破坏。

### 增量构建

每篇 Markdown 文件的内容经 xxHash3 哈希后记录在清单中，未变更的文章直接跳过解析与翻译，只有真正变化的文件会重新进入生成管线。写第二篇文章时，第一篇不会重复付费翻译。

### 内存感知的批量调度

生成器按可用内存对文章分批处理，批间强制回收，哪怕面对上千篇文章的站点也能在普通开发机上稳定完成构建，而不是把希望寄托在机器内存足够大上。

### 主题即完整项目

主题是一个包含 `.kecare` 模板目录与完整前端技术栈（如 Nuxt + Tailwind）的项目。主题作者在 `.kecare` 内以约定命名编写 TypeScript 模板：

- `*.article.ts` —— 文章详情页模板，每篇文章调用一次
- `*.list.ts` —— 列表页模板，按语言分组、排序、分页
- `*.menu.source.ts` —— 菜单声明，文件名自动转换为 hash 链接
- `*.archives.ts` —— 归档页模板

模板返回 `urlPath`、`fsPath` 与 `template` 三元组，页面的路由、落盘位置与内容由主题全权决定。生成器不关心你用什么组件、什么样式方案——它只负责把数据交到你的函数手上。

### 一致的内容寻址

每篇文章按其相对路径生成短 hash，多语言版本共享同一个 hash，最终 URL 形如 `articles/<lang>/<hash>`。同一篇文章的所有语言版本天然形成稳定、可预测的地址结构，语言间的跳转关系不言自明。

### 预渲染静态输出与浏览器端 SDK

站点经预渲染产出每页独立的静态 HTML，可部署到任何静态托管（如 EdgeOne Pages）。浏览器端由轻量运行时 SDK 接管交互：侧边栏目录、Shiki 代码高亮、代码复制、Tabs 切换、语言切换——这些内容站必备的交互不需要主题作者重复造轮子。

### 开箱即用的 Markdown 扩展

数学公式（KaTeX）、分组选项卡（Tabs）等常用能力内建在 Markdown 解析管线中，无需主题自行集成。

## 生态愿景

Kecare 的主题分发采用**模板仓库**模式：主题作者发布的主题自带前端技术栈与部署说明，用户只需要三步——

1. 全局安装 kecare CLI；
2. 取下一份主题，在 `.kecare/articles/` 里写 Markdown；
3. 运行 `kecare gen`，按照主题内的说明完成构建与部署。

生成阶段不需要在项目内安装任何依赖——CLI 以平台二进制形式分发，模板由内嵌的 Bun 运行时直接执行。主题作者不需要迎合框架的组件规范，用户不需要理解框架的内部机制，双方只通过 `.kecare` 这一层约定协作。

内容归作者，管线归 Kecare，表现层归主题——各得其所。
